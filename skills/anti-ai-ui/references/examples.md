# 改造前后对照

以下均为原创的虚构情景；数字、日期、格式限制、状态和按钮只是示例，不能复制为真实业务事实。落地前从产品约束、接口返回或现有行为核实。文字线框用于说明信息优先级，不是所有页面都应套用的布局模板。

## 1. 经营后台：从装饰性卡片墙到待办与比较

**情景：**运营人员每天查看经营情况，优先找出需要处理的异常，再比较各区域表现。

**改造前：**

```text
欢迎来到智能经营驾驶舱
全方位洞察业务趋势，助力每一次科学决策

蓝色左彩条卡片：订单量 12,480   绿色左彩条卡片：收入 ¥83,600
紫色左彩条卡片：异常 18        橙色左彩条卡片：完成率 97.6%
每张卡片下：数据可能存在误差，仅供参考，请以实际为准

业务概览 / 数据洞察 / 更多分析 / 智能建议（同等醒目）
真正待处理的订单列表在页面底部
```

**改造后：**

```text
经营概况                         日期 [11 月 8 日]  区域 [全部]
待处理异常 18 条                                      [查看异常]

订单量 12,480       收入 ¥83,600       完成率 97.6%
统计：已支付订单；收入不含退款。更新于 09:10

区域表现                         [筛选]  [导出]
区域      订单量      收入        完成率      待处理异常
北区      …           …           …           …
南区      …           …           …           …
                                                    [指标口径]
```

**保留依据：**日期、区域、单位、直接影响判断的口径与更新时间放在比较对象附近。复杂计算细节进入“指标口径”；若数据缺失会改变结论，缺失状态仍需在相关指标处直接显示。卡片可以保留给独立对象或明确可点击的入口；没有语义的左彩条和重复免责声明删除。

**验收关注：**无需滚到页面底部即可进入异常处理；用户能识别当前筛选范围并比较区域。指标数量由工作任务决定，不为了凑整齐的四宫格添加无用指标，也不为了“极简”删除高频比较列。

## 2. 导入表单：约束在操作前，错误在定位处

**情景：**用户上传客户资料。已核实的示例约束是 XLSX、最大 10 MB、必填“客户名称”和“联系电话”，导入会跳过重复客户。

**改造前：**

```text
使用须知
这里支持批量导入客户，可以帮助您提高工作效率。请注意格式、大小、
必填字段、重复规则和日期要求。导入可能失败，请仔细核对。
（继续展示全部字段说明和十几行格式示例）

[选择文件]                                           [提交]
失败后：导入失败，请检查数据后重试
```

**改造后：**

```text
导入客户
[下载模板]

客户文件
[选择文件]
XLSX，最大 10 MB；必须包含客户名称和联系电话

重复客户将跳过，不会覆盖现有资料
[查看字段格式与示例]

[导入客户]
```

错误发生后，在文件字段旁或结果区显示已确认的信息：

```text
有 2 行未导入，其余 38 行已导入
第 7 行：缺少联系电话
第 19 行：缺少客户名称
[下载错误明细]  [选择修正后的文件]
```

**保留依据：**格式、大小、必填字段和重复处理方式会影响提交，必须在提交前可见。字段格式的长示例可展开。成功、部分成功和整体失败分别描述；若系统实际上执行整批回滚，就写“本次未导入任何记录”，不能套用部分成功文案。

**验收关注：**用户在选择文件前能找到限制；失败后能定位到真实行号并恢复。展开控件支持键盘，错误与字段关联；不把必需限制塞进悬浮提示，也不凭空提供后端尚不支持的错误明细下载按钮。

## 3. 数据延迟与缺失：把不确定性说具体

**情景：**查询结果附带已核实的更新时间和缺失范围。示例中，当前为 10:00，最新数据截止 08:30，南区数据尚未到达。

**改造前：**

```text
今日收入 ¥83,600
数据可能不太准确，仅供参考，以实际为准
```

**改造后：**

```text
今日收入（截至 08:30） ¥83,600
暂不包含南区；当前合计不能代表全部区域
[刷新数据]  [查看缺失范围]
```

**保留依据：**截止时间、缺失范围和对合计的影响会改变判断，应与数值同处显示。只有系统确实支持刷新并可能获取新数据时才提供该按钮。详细数据来源可放在“查看缺失范围”中；不能用折叠说明掩盖当前数值不完整。

若接口只返回失败、没有时间或原因，则改为“暂时无法加载收入数据”并提供可用的重试入口。若展示缓存且不知道缓存时间，应标明“显示上次成功加载的数据，更新时间未知”，不要推测“预计 5 分钟恢复”或“由于网络波动”。技术原因待查的事实留在工程沟通中；用户需要的是可确认的状态、影响和下一步。

**验收关注：**未知、未加载和真实的 0 不混用；更新时间来自数据而非页面时钟；不能通过删除“可能”把未经核实的判断改成确定结论。确有必要的风险或法定提示按业务要求保留。

## 4. 品牌与专家界面：允许有目的的表达与密度

**情景：**产品有明确的紫色品牌；专家工作台需要同时比较多个实时队列。品牌规范和工作任务都已确认。

**改造前的错误修法：**

```text
“去 AI 味” → 所有紫色和渐变改成灰色
“减少信息” → 所有队列藏进逐个展开的卡片
“更简洁”   → 去掉文字状态，只保留红黄绿圆点
```

**改造后：**

```text
品牌标志使用既定紫色；品牌展示区域保留经过设计的渐变
工作区使用稳定的表头、对齐和分组，减少无意义的重复装饰
队列      当前任务      等待时间      状态         操作
队列 A    …             …             处理中       [查看]
队列 B    …             …             需处理       [处理]
```

**保留依据：**品牌颜色提供身份识别，相关列支持同时比较，状态文字提供不依赖颜色的含义。选中行可以保留单侧指示线，但还应有可感知的选中状态；渐变不妨碍文字阅读，装饰动效不阻碍连续操作。

**验收关注：**专业用户完成同一任务无需更多展开或页面跳转；颜色、焦点和文字仍清晰；保留用户指定的视觉方向。密度高不自动等于信息爆炸，使用紫色或渐变也不能单独证明界面有问题。
