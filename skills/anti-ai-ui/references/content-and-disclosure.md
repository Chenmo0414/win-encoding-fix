# 文案与信息分层

适用于说明堆积、含糊状态、重复免责声明和“全部直接展示在最外层”的界面。依据包括 [NN/g 渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)、[GOV.UK Details](https://design-system.service.gov.uk/components/details/)、[表单提示](https://design-system.service.gov.uk/components/text-input/) 与 [Carbon 内容指南](https://www.carbondesignsystem.com/building-blocks/foundations/content)。下面的中文写法是原创示例，不是对源文档的翻译。

## 给每句话一个去处

按“是否改变当前选择、是否多数人都需要、是否能靠控件本身表达”判断，不能只按文字长度判断。

| 内容 | 合适位置 | 处理原则 |
|---|---|---|
| 当前对象、状态、主要操作 | 主内容区 | 第一眼能找到，描述和按钮不要互相复述 |
| 金额/单位/时间范围/比较基准 | 相邻指标、列头或筛选区 | 影响理解时保持可见，避免每个单元格重复同一解释 |
| 多数人需要的输入格式、资格或限制 | 对应字段旁或提交前 | 尽量简短，必要时配示例；不能只放 placeholder |
| 影响当前决定的数据缺失、估算、延迟 | 相邻结果的显著状态 | 简要说明范围与影响，细节可展开 |
| 费用、数据删除等关键后果 | 操作发生前的相关位置 | 保留必要说明，遵循现有产品确认/撤销机制 |
| 少数人需要的规则、例外、完整口径 | 有具体名称的展开区或详情 | 入口预告内容，如“查看统计口径”；不要全写“了解更多” |
| 短词定义 | 上下文帮助；可用适当 tooltip | 不承载必读流程或长内容；支持键盘和触屏访问 |
| 当前字段错误 | 字段旁，必要时另有错误摘要 | 指明问题和可执行的修正方式 |
| 技术诊断、内部取舍、尚未证实的原因 | 开发沟通、日志或支持详情 | 不把工程师的不确定性铺成用户界面的免责声明 |
| 重复标题、空泛宣传、无助于行动的说明 | 删除 | 不是每句都必须找到新容器 |

渐进披露要减少理解负担，也要计算额外点击成本。对需要反复比较的信息，保留同屏通常比拆成多个详情页更好。

## 对“不确定”的四种处理

1. **已证实的事实**：直接说事实。不要把已经知道的失败写成“可能出现异常”。
2. **真实未知或估算**：保留未知、范围和对任务的影响；有依据才提供时间、覆盖率或原因。
3. **开发者猜测**：回到代码、接口或日志验证。未验证前不写成产品原因，例如擅自归咎“网络问题”。
4. **无差别兜底**：若“仅供参考/请以实际为准”没有具体对象、必要依据或动作价值，删掉；已确认的法律、合同或行业要求不由这项审美规则覆盖。

优先使用“已知状态 → 对当前任务的影响 → 真实可用的下一步”。这不是必须凑齐三句话的模板；一行能说清时就用一行。未知原因不代表必须在页面上写“原因未知”，只需不编造。

| 冗余或含糊写法 | 可替换写法 | 前提 |
|---|---|---|
| 在这里您可以查看和管理所有导入任务 | 删除；标题用“导入任务”，动作用“导入文件” | 标题和控件已表达用途 |
| 点击下方按钮开始创建一个新的项目 | “创建项目” | 无需解释额外前置条件 |
| 系统可能尚未同步，请稍后再试 | “数据加载失败”＋“重试” | 已知请求失败且产品提供重试；不能假设同步原因 |
| 数据可能不完整，仅供参考 | “部分数据未返回，总计暂不可用”＋“重新加载” | 接口明确返回部分数据，且允许重新加载 |
| 暂无数据 | “没有符合筛选条件的记录”＋“清除筛选” | 已确认是筛选结果为空 |
| 暂无数据 | “尚未导入记录”＋“导入文件” | 已确认是首次使用，且用户有导入权限 |
| 操作失败，请联系管理员 | “没有编辑权限”＋真实存在的申请入口 | 已确认权限原因；没有入口时不能伪造按钮 |
| 温馨提示：我们采用先进技术确保数据安全可靠 | 删除；如确有决策所需限制则说明具体限制 | 不编造安全承诺、认证或服务保证 |

不要把示例数字、延迟时间、已处理行数或故障原因复制到真实产品。必要状态来自接口和已有逻辑；缺失时记录待确认项，不伪造成功、空列表或零。

## 防止删减后的倒退

- 表单保留可见标签。必要帮助与控件关联；长说明不全部塞进辅助技术每次都会读出的描述。
- 原生 `details/summary` 或现有可访问组件通常足够。自定义展开按钮需正确更新 `aria-expanded`，支持 Enter/Space；`aria-controls` 按实现需要使用。参见 [WAI Disclosure](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)。
- Tooltip 不能成为关键输入规则、错误解释或风险的唯一入口。折叠后的内容要有可发现、可操作的入口。
- 合并多个提示时检查出现条件和对象范围；不同字段、不同失败原因不能因文案相似而被错误合并。
- 错误处理应帮助恢复任务，不能仅把错误文字变短；也不要擅自承诺“自动重试”“已保存”等未实现行为。
- 持续使用所需的关键信息不能只在新手引导出现一次；专家模式也要保留可访问的帮助入口。
